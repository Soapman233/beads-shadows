# 材料商城和会员的本地演示

商城使用独立的材料库存。根据已保存图纸的缺料清单，商城按已匹配色号和每包颗数计算购买包数。下单锁定可售库存，订单保留当时的数量、单价、色号和规格。

## 启用演示

在独立 MySQL 开发库应用迁移。沿用项目的管理员创建流程，配置 `BEAD_MOCK_PAYMENTS=1` 后重启本机服务。所有款项以人民币分表示。商城接口中的 `simulation` 为真，表示该订单的付款、退款和发货均为本地演示。

1. 管理员发布一个有明确来源的色卡版本，再用其中的稳定色号创建商品。填写规格、每包颗数、分价格和可售包数。
2. 普通账号可添加材料到购物车，也可从对应的图纸版本预览缺料方案并确认加入。无法匹配的色号会单独列出。
3. 创建订单会预留库存。用户可模拟付款成功或失败，也可以在付款前取消。服务每 30 秒尝试释放已经过期的待付款订单，每笔默认预留 15 分钟。
4. 在发货前，用户可申请退款。管理员可登记模拟退款并释放商品库存，或为已付款的材料订单登记模拟发货。
5. 管理员可建立带说明和天数的会员套餐。购买套餐的本地模拟付款完成后生成权益记录。退款撤销相应权益，到期自动显示失效。管理员也可直接发放权益。

## 事务和后续支付接入

用户下单时使用唯一请求编号。重复提交同一请求编号返回已有订单。每次下单按固定顺序锁定商品并检查可售量，在同一事务内写入数量变动和快照。MySQL 死锁或锁等待超时会触发有限次本地重试。

付款和退款事件以渠道及事件编号去重。应用前核对订单、渠道、金额和币种，并在订单锁内验证状态转换。订单状态及库存释放在同一事务提交。变更商品的“可售包数”针对未预留数量，历史订单和预留量由订单流程管理。

`PaymentProvider` 定义了外部回调验签后的业务接口。E05 依赖真实商户的测试配置。接入时应对照所选渠道的官方回调文档，实现原始报文验签、商户及消息时效验证，并在订单锁内应用已验证事件。渠道实际扣款后才到达的过期事件需按渠道规则对账，目前演示渠道在订单过期后禁止生成付款。当前已接入 `local_mock`。

会员权益是按期限保存的身份与套餐权益说明。它与百炼次数独立，演示流程不会自动扣费或续费。
