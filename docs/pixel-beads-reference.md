## 适配本项目的实现

本项目继续使用 maxcleme/beadcolors 的现有220色子集及MIT声明。色卡与历史作品色值不变，未引入参考站的291色数据。现有流水线仍为原图规范化 → 主体掩码 → 网格采样 → 有限色表选择 → 色号映射 → 人工修整 → 项目/施工导出。本轮不重写配色距离，不将界面变化当作色差优化。

1. **先恢复可用性**：useGeneration 在消息边界重新构造普通约束数组，避免Vue响应式代理导致DataCloneError；存储队列统一从完整快照读ID、项目和资源；项目校验复制box。
2. **可视化细节区域**：RegionPicker 可拖动设定规范化矩形，保留坐标输入作为精确及键盘入口。拖动只改草稿，点击确认才进入有效设置；非法区域不写入作品。新建、换图、恢复统一同步/重置待应用设置。
3. **同条件对照**：细节生成同时返回默认与细节候选。图片、掩码、宽度、色数上限和mean采样相同，默认算法仍为hue4；由用户选择是否替换当前图纸。
4. **查色与用量**：PalettePanel 按色号/HEX筛选，按用量或色号排序。实际色数由cells统计，零用量候选不计色数；色卡来源、版本及许可折叠显示，导入旧项目缺来源时如实提示。
5. **施工检查**：编辑画布可开关5/10格粗网格；格内标记默认关闭，150%以上显示短数字，空格×。编号沿用打印的已用色顺序，提供对应图例。这些操作只影响显示，不写cells、不改变导出。
6. **准确提示**：本轮约束和swap候选不再被误标为“旧版配色”；约束候选明确记录mean采样元数据。

继续保留原三步主流程及已有采样对比。没有加入网站的账号、社区、云端AI重绘或多层系统，避免扩大安装和使用负担。界面无slogan，解释信息按需展开。

## 验证结果

- 前端测试29/29通过，类型检查与生产构建通过。日志在本地output/pixel-iteration-tests.log、pixel-iteration-build.log。
- T 用隔离的修复前HEAD源码副本，确认Worker代理和存储快照两项失败；修复后相关6项通过。临时源码副本已删除，未回滚产品文件。
- 新Worker测试使用真正Vue响应式输入和原生MessageChannel，覆盖消息传输及buffer不被detach；不是算法或浏览器替身验收。
- 另在独立8768来源实际使用公开geometric.png，经过正常界面导入、整图掩码、拖框、H7必选、生成、选择、保存、刷新恢复及新建。两张同条件候选均64×64、3752颗、12实际色；H7可为零用量候选。
- 实际拖框得到 `[0.155,0.169,0.805,0.707]`，刷新后输入和必选H7恢复；故意将左边界改为0.95被拒绝、生成禁用。新建后默认区域输入0.25/0.2/0.75/0.55、必选为空，空约束也能生成。
- 浏览器实际打开150%格内标记、开关粗网格、筛选色号、改变排序。显示操作前后下载的两份项目JSON逐项完全相同；没有哈希。最终构建重新载入后界面正常，未见控制台错误。
- 未重跑无改动后端或SAM，未把先前实际PDF、用户角色图实验写成本轮新执行。该角色图的既有ROI负结果仍有效，不宣称色差已解决。

本地运行入口：`http://127.0.0.1:8768/`。这一来源用于独立验收，不会自动显示其他端口的项目；需要时通过下载/打开项目转移。服务本轮以CPU轻量模式运行，不代表轻薄本性能实测。
